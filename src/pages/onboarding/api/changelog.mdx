# Historial de cambios - Changelog

Este archivo contiene las mejoras y actualizaciones que se hagan en Onboarding API.

Onboarding no versiona sus rutas, así que los cambios se identifican por su fecha. Dos criterios que
conviene conocer para leer esta lista:

- **`result` es un objeto extensible.** Pueden aparecer claves nuevas sin que se considere un cambio
  incompatible: ignora las que no conozcas en lugar de rechazar la respuesta.
- **Pueden aparecer códigos de fallo nuevos** en `status.reason`. Deja siempre un caso por defecto al
  interpretarlo.

## 2026-08-24

### Cambió:

- **La actualización de un comercio usa `PATCH`, no `PUT`.** La ruta es ahora
  `PATCH /api/merchants/{merchantId}`. El verbo describe lo que el endpoint siempre hizo: escribir
  solo los campos que el cuerpo nombra, en lugar de reemplazar el comercio entero. Nada más cambia —
  la misma URL, el mismo cuerpo, los mismos headers, los mismos códigos de respuesta y el mismo
  flujo de consulta del proceso. La creación sigue siendo `POST /api/merchants`.

### Nuevo:

- `sites[].type` admite el valor `POS_AIR`, punto de venta de aerolínea, además de los cinco que ya
  aceptaba. Lo reconocen tanto la creación como la actualización de un comercio, y no cambia nada
  más del contrato: un sitio de este tipo se declara y opera como cualquier otro.
- En `sites[].metadata`, el valor de un nombre ya no tiene que ser un dato suelto: ahora también
  puede ser **un objeto o una lista**, donde antes respondían `422`. Los límites de tamaño del bloque
  no cambian.
- La referencia de la API muestra ahora, a modo de ejemplo, las claves que usa una integración
  concreta. Son solo eso, un ejemplo: los nombres los sigue eligiendo el comercio y la API no valida
  ninguno.
