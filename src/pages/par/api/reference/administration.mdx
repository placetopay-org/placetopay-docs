## Sincronizar un comercio {{ id: 'sync-merchant', tag: 'PUT', label: '/api/merchants/{coreId}' }}

<Row>
  <Col>
    Crea el comercio en PAR o actualiza el que ya existe con ese `coreId`, junto con su socio de tipo comercio. Es idempotente: repetir la misma petición deja el mismo resultado. Más detalle en [Comercios y sitios](/par/administration/merchants-and-sites).

    <Note type="warning">
      El comercio queda activo solo si `merchant.status` es `ACTIVE` **y** `settings.enabled` es `true`. Si queda inactivo, o si cambia su `authorizationCode`, PAR revoca las sesiones abiertas de su socio.
    </Note>

    <ApiReader
      path="/api/merchants/{coreId}"
      type="params"
      api={props.refs}
    />

    <ApiReader
      path="/api/merchants/{coreId}"
      method="put"
      type="header"
      api={props.refs}
    />

    <ApiReader
      path="/api/merchants/{coreId}"
      method="put"
      api={props.refs}
    />

  </Col>
  <Col sticky>
    <CodeGroup title="Solicitud" tag="PUT" label="/api/merchants/{coreId}">
```bash {{ title: 'Sincronizar el comercio' }}
curl --request PUT \
  --url '{URL_BASE}/api/merchants/10' \
  --header 'Accept: application/json' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Bearer {TU_TOKEN}' \
  --data '{
    "issuer": "operator@example.com",
    "locale": "es",
    "merchant": {
      "coreId": 10,
      "name": "Comercio de prueba",
      "authorizationCode": "MerchantSecret123",
      "documentType": "NIT",
      "document": "900123456",
      "city": "Santiago",
      "country": "CL",
      "status": "ACTIVE"
    },
    "settings": {
      "enabled": true,
      "requiresAutopayApproval": true,
      "notificationEmail": "notifications@example.com"
    }
  }'
```
    </CodeGroup>
  </Col>
</Row>

## Sincronizar un sitio {{ id: 'sync-site', tag: 'PUT', label: '/api/sites/{coreId}' }}

<Row>
  <Col>
    Crea el sitio en PAR o actualiza el que ya existe con ese `coreId`. El comercio al que pertenece debe estar sincronizado antes. La respuesta devuelve el `commerceCode` del sitio: es el valor que el comercio envía en el header `Commercecode`. Más detalle en [Comercios y sitios](/par/administration/merchants-and-sites).

    <Note>
      El sitio queda activo solo si `site.status` es `ACTIVE` **y** `settings.enabled` es `true`. Si no envías `site.commerceCode`, PAR conserva el actual o genera uno nuevo.
    </Note>

## Actualizar un socio emisor {{ id: 'update-partner', tag: 'POST', label: '/api/partners/{partnerId}' }}

<Row>
  <Col>
    Reemplaza la configuración de un socio de tipo `issuer`: envía siempre todos los campos obligatorios, no solo los que cambian. Si el socio es de tipo comercio, responde `422`: esos socios se actualizan al [sincronizar el comercio](#sync-merchant).

    <Note type="warning">
      Si cambias la `secretKey` o desactivas el socio con `enabled: false`, PAR revoca sus sesiones abiertas. Para rotar la llave, envía la nueva en `secretKey` y entrégasela al emisor.
    </Note>

    <ApiReader
      path="/api/partners/{partnerId}"
      type="params"
      api={props.refs}
    />

    <ApiReader
      path="/api/partners/{partnerId}"
      method="post"
      type="header"
      api={props.refs}
    />

    <ApiReader
      path="/api/partners/{partnerId}"
      method="post"
      api={props.refs}
    />

  </Col>
  <Col sticky>
    <CodeGroup title="Solicitud" tag="POST" label="/api/partners/{partnerId}">
```bash {{ title: 'Rotar la llave secreta' }}
curl --request POST \
  --url '{URL_BASE}/api/partners/7' \
  --header 'Accept: application/json' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Bearer {TU_TOKEN}' \
  --data '{
    "name": "Banco de prueba",
    "type": "issuer",
    "userDocumentType": "CLRUT",
    "enabled": true,
```

```bash {{ title: 'Desactivar el socio' }}
curl --request POST \
  --url '{URL_BASE}/api/partners/7' \
```
