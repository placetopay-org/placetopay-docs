## Introducción a EBT Online

La Transferencia Electrónica de Beneficios (EBT, por sus siglas en inglés) permite a los participantes del Programa de Asistencia Nutricional (PAN, o NAP por sus siglas en inglés) pagar por alimentos elegibles utilizando sus beneficios. En Puerto Rico, estos beneficios pueden utilizarse únicamente en comercios autorizados por ADSEF. Cuando un participante realiza una compra, el sistema EBT procesa la transacción en línea, debita los fondos de la cuenta del ciudadano y liquida el pago correspondiente al comercio.

A nivel federal, estos programas son supervisados por el Food and Nutrition Service (FNS) del Departamento de Agricultura de EE. UU. (USDA). A diferencia de Estados Unidos (donde opera el programa SNAP), Puerto Rico administra un bloque de fondos federales distinto conocido como el PAN. El uso de estos beneficios mediante comercio electrónico está estrictamente limitado a transacciones procesadas por comercios certificados y localizados físicamente en Puerto Rico.

A nivel local, la Administración de Desarrollo Socioeconómico de la Familia (ADSEF) es la agencia gubernamental responsable de administrar el PAN. ADSEF actúa como el ente oficial que evalúa, aprueba y certifica a los comercios para que puedan aceptar EBT Online, asegurando que cumplan con las regulaciones tecnológicas y operativas.

### Estructura de fondos: los bolsillos EBT

Al integrar pagos con la Tarjeta de la Familia, el comercio debe considerar que los beneficios se dividen en dos balances o "bolsillos" independientes:

- **EBT Regular (Alimentos)**: Fondos restringidos exclusivamente para la compra de alimentos elegibles aprobados por el programa.
- **EBT Cash (Efectivo)**: Fondos con mayor flexibilidad que pueden utilizarse para comprar artículos no alimenticios o cubrir otros gastos.

Al procesar el pago, el sistema de Placetopay manejará la transacción contra el bolsillo correspondiente según la instrucción del comercio.

### Certificación y responsabilidades del comercio

Para procesar transacciones EBT en línea, el comercio debe completar la certificación funcional ante ADSEF, quien audita la experiencia de usuario (UX) para validar los controles normativos. Al integrar Placetopay con EBT, el comercio asume la responsabilidad de gestionar la lógica del carrito de compras y debe garantizar las siguientes reglas de negocio:

1. **Identificación de artículos**: El comercio es el único que conoce el detalle del carrito y debe identificar visualmente de manera precisa cuáles productos son elegibles para el pago con fondos del PAN.
2. **Restricción de cargos adicionales**: Las regulaciones federales prohíben cobrar gastos de envío, impuestos u otros recargos administrativos utilizando el método de pago EBT.
3. **Flujo de pago dividido (Split Tender)**: Los artículos elegibles para EBT deben cobrarse primero. Si el carrito contiene artículos aplicables, el comercio debe consultar al cliente si desea utilizar su tarjeta EBT. De ser así, debe redirigir al cliente a una primera sesión en Placetopay restringida exclusivamente a los métodos de pago EBT. Una vez el usuario complete esta transacción y retorne a la tienda, el comercio deberá generar una nueva sesión de pago convencional (excluyendo la opción EBT) para saldar cualquier balance restante de artículos no elegibles y recargos.

## Flujo de pago
1. El usuario selecciona EBT como método de pago en el checkout.
2. Ingresa los datos de su tarjeta EBT.
3. Completa la validación mediante OTP (código de un solo uso).
4. Placetopay procesa la transacción y notifica al comercio y al usuario el estado de la operación.

## **Opciones de integración**

- **Integraciones por**: [Webcheckout](/checkout)
El medio de pago **EBT** está disponible a través de **Webcheckout**, ofreciendo un proceso de pago seguro y automatizado. **Placetopay** gestiona la transacción, garantizando una experiencia fluida para el usuario.

- **Integraciones por**: [Gateway](/gateway)
Para integraciones avanzadas, **Gateway** permite capturar y procesar pagos **EBT** directamente desde la plataforma del comercio, ofreciendo mayor control en escenarios específicos como:  
- Integraciones con sistemas de audiorespuesta.  
- Procesamiento de múltiples transacciones con la misma información del tarjetahabiente. 


## Billetera Placetopay

- EBT es compatible con Wallet Placetopay, lo que permite a los usuarios almacenar información de sus tarjetas para realizar compras rápidas y seguras sin necesidad de ingresarla manualmente en cada transacción.

## Restricciones

- Las tarjetas EBT no pueden utilizarse en determinados lugares, como licorerías, casinos y otros establecimientos de juego.

## Integración por Webcheckout  
El medio de pago **EBT** permite a los comercios aceptar pagos electrónicos a través de **Webcheckout**, con un proceso seguro y automatizado. EBT admite dos tipos de pago: **Regular** y **Cash**, los cuales pueden utilizarse en la misma transacción.  
Para iniciar una sesión de pago con este método, es necesario enviar los siguientes parámetros en la solicitud.  

### **Creación de sesión de pago**  
Para [crear una sesión](/checkout/api/reference/session#create-a-session), se deben incluir los siguientes campos:  

- **paymentMethod**: Define el tipo de pago EBT a utilizar. Se deben enviar los siguientes códigos:  
  - **ebt**: Para pagos regulares y Cash.  
  - **EBTCH,EBTRG**: Para pagos regulares y Cash.  
  - **EBTCH**: Para pagos solo con Cash.  
  - **EBTRG**: Para pagos solo con Regular.  

- **metadata**: Define el tipo de entrega. Se pueden enviar las siguientes opciones:  
  - `DIRECT_DELIVERY`,  
  - `CUSTOMER_PICKUP`, 
  - `COMMERCIAL_SHIPPING`, 
  - `OTHER`, 
  - `NOT_AVAILABLE`

- **payment.shipping.address**: Información de dirección del comprador.
    - `country`, `state`, `city`, `postalCode`, `street`, `phone`

#### Uso de `paymentMethod` para sesiones EBT

Para que la sesión de Webcheckout muestre únicamente EBT, el comercio debe filtrar el medio de pago desde su petición de [creación de sesión](/checkout/api/reference/session/) enviando el campo `paymentMethod` con alguno de los códigos EBT descritos arriba. Con este filtro, el usuario solo verá las opciones EBT habilitadas.

Si el comercio **no envía** el campo `paymentMethod`, la sesión no se limita a EBT y el usuario podrá utilizar los demás medios de pago habilitados en el sitio. Por esta razón, no se debe enviar el filtro cuando se quiera permitir métodos distintos de EBT, por ejemplo en la sesión convencional que salda el balance restante en un pago dividido (Split Tender).

#### Cuándo y cómo enviar `metadata.EBTDeliveryIndicator` y `payment.shipping.address`

Ambos datos deben enviarse en la creación de la sesión cuando esta incluye el medio de pago EBT:

- **`metadata.EBTDeliveryIndicator`**: indica cómo recibirá el comprador su pedido. Se envía dentro de `metadata` con uno de los valores `DIRECT_DELIVERY`, `CUSTOMER_PICKUP`, `COMMERCIAL_SHIPPING`, `OTHER` o `NOT_AVAILABLE`.
- **`payment.shipping.address`**: se envía dentro de `payment.shipping` con los campos `country`, `state`, `city`, `postalCode`, `street` y `phone` del comprador.

No es necesario enviarlos en la sesión convencional (sin EBT) que se crea para cobrar el balance restante.

## Ejemplos de solicitud

**Sesión EBT (Regular y Cash)**

```json
{
    ...
    "payment": {
        "reference": "ebt_payment",
        "description": "test ebt",
        "amount": {
            "currency": "USD",
            "total": "10"
        },
        "shipping" : {
            "address": {
                "country" : "PR",
                "city" : "San Juan",
                "street" : "Calle Ejemplo 123",
                "state" : "PR", 
                "postalCode" : "00901",
                "phone" : "+1-787-555-1875"
            }
        }
    },
    "paymentMethod" : "ebt",
    "metadata": {
        "EBTDeliveryIndicator": "DIRECT_DELIVERY"
    },
    ...
}
```

### **Cobro usando token**
Para realizar un [cobro usando token](/checkout/api/reference/token#charge-using-token), se deben enviar los mismos parámetros que en la creación de una sesión, más el siguiente campo:

- **provider** Código del proveedor de procesamiento EBT:
  - `EBUS`, 
  - `EBUS/EBTCH`, 
  - `EBUS/EBTRG`

- **instrument.pin**: Código PinPad.
Para utilizar este método de cobro, la integración debe incluir el servicio de [PinPad](/sdks/pinpad) para generar y validar el código PIN. Este código debe ser enviado en la solicitud dentro de la propiedad: 
`CollectRequest.instrument.pin`

```json
{
    ...
    "payment": {
        "reference": "ebt_collect",
        "description": "test ebt",
        "amount": {
            "currency": "USD",
            "total": 10
        },
    },
    "instrument": {
        "token": {
            "token": "faketoken12f233bd8f5d42138d681bf07ea8295429df07a4af287703e30c891"
        },
        "pin" : "7567F2E727200490"
    },
    "provider" : "EBUS/EBTCH"
    ...
}
```
