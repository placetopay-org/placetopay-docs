ATH Móvil allows the payer to authorize a charge from the application installed on their phone. The payment is processed asynchronously: the initial response normally remains `PENDING` and is later updated with the payer's decision.

## Payment flow {{ id: 'payment-flow' }}

1. The merchant creates a Webcheckout session or processes a transaction through Gateway.
2. The payer receives the charge request and approves or rejects it from ATH Móvil.
3. The transaction remains `PENDING` while waiting for the decision.
4. Placetopay queries the result and updates the transaction.
5. The merchant obtains the final status by querying the Webcheckout session or the Gateway internal reference.

![ATH Móvil payment flow](/en/payments/ath-movil/pm-ath-movil-flow.png)

## Prerequisites {{ id: 'requirements' }}

- Request ATH Móvil enablement for the Placetopay site that will process the charges.
- The merchant category code (MCC) must be configured.
- Process payments in `USD`.
- Use the `ATHMV` code to identify the payment method.
- Send the payer's phone number with Puerto Rico's international dialing code, for example `+1787...` or `+1939...`.

## Webcheckout integration {{ id: 'webcheckout-integration' }}

Webcheckout manages the payment experience and status updates. To display only ATH Móvil, create a session through [`POST /api/session`](/en/checkout/api/reference/session#create-a-session) and send `paymentMethod` with the `ATHMV` value.

If you include `payer`, the data is prefilled and cannot be modified by the payer. If you omit it, Webcheckout will request the required data before processing the payment.

### Session creation request

```json
{
  "auth": {
    "login": "aabbccdd1234567890aabbccdd123456",
    "tranKey": "ABC123example456trankey+789abc012def3456ABC=",
    "nonce": "NmJmMG1hNmJmOQ==",
    "seed": "2026-07-31T10:15:30-04:00"
  },
  "payment": {
    "reference": "ATHMV-ORDER-1001",
    "description": "Test purchase",
    "amount": {
      "currency": "USD",
      "total": 10
    }
  },
  "payer": {
    "name": "John",
    "surname": "Doe",
    "email": "john.doe@example.com",
    "mobile": "+19391111114"
  },
  "paymentMethod": "ATHMV",
  "returnUrl": "https://merchant.example.com/payment-result",
  "ipAddress": "127.0.0.1",
  "userAgent": "Mozilla/5.0"
}
```

### Session creation response

```json
{
  "status": {
    "status": "OK",
    "reason": "PC",
    "message": "The request has been successfully processed",
    "date": "2026-07-31T10:15:31-04:00"
  },
  "requestId": 12345,
  "processUrl": "https://checkout-test.placetopay.com/session/12345/example-session-key"
}
```

Redirect the payer to `processUrl`. After payment, do not use the browser return as financial confirmation: query [`POST /api/session/:requestId`](/en/checkout/api/reference/session#query-a-session) and validate the status reported by Placetopay.

## Gateway integration {{ id: 'gateway-integration' }}

Gateway allows the merchant application to initiate the charge. Send a request to [`POST /gateway/process`](/en/gateway/api/reference/transaction#process-request) with the payer's phone number and the `ATHMV` redirection instrument.

### Processing request

```json
{
  "auth": {
    "login": "aabbccdd1234567890aabbccdd123456",
    "tranKey": "ABC123example456trankey+789abc012def3456ABC=",
    "nonce": "NmJmMG1hNmJmOQ==",
    "seed": "2026-07-31T10:15:30-04:00"
  },
  "payment": {
    "reference": "ATHMV-ORDER-1001",
    "description": "Test purchase",
    "amount": {
      "currency": "USD",
      "total": 10
    }
  },
  "payer": {
    "name": "John",
    "surname": "Doe",
    "email": "john.doe@example.com",
    "mobile": "+19391111114"
  },
  "instrument": {
    "redirection": {
      "paymentMethod": "ATHMV"
    }
  },
  "ipAddress": "127.0.0.1",
  "userAgent": "Mozilla/5.0"
}
```

### Initial response

An accepted initial response is `PENDING`. Store `internalReference`, because it is the identifier required to query the result.

```json
{
  "status": {
    "status": "PENDING",
    "reason": "?-",
    "message": "Pending transaction",
    "date": "2026-07-31T10:15:31-04:00"
  },
  "internalReference": 485,
  "reference": "ATHMV-ORDER-1001",
  "paymentMethod": "ATHMV",
  "franchise": "athmv",
  "franchiseName": "ATH Móvil",
  "amount": {
    "currency": "USD",
    "total": 10
  },
  "provider": "ATH-MOVIL",
  "redirection": {
    "paymentMethod": "ATHMV",
    "processURL": "https://rest.test/mock/redirection/example",
    "additional": {
      "expiration": "2026-07-31T10:35:31-04:00"
    }
  }
}
```

`redirection.additional.expiration` indicates when payment confirmation expires. `redirection.processURL` is returned only in sandbox to open the simulator; in production it is normally `null`, because the payer completes approval from ATH Móvil.

### Querying the result

Query [`POST /gateway/query`](/en/gateway/api/reference/transaction#query-request) with the internal reference from the initial response.

```json
{
  "auth": {
    "login": "aabbccdd1234567890aabbccdd123456",
    "tranKey": "ABC123example456trankey+789abc012def3456ABC=",
    "nonce": "NmJmMG1hNmJmOQ==",
    "seed": "2026-07-31T10:16:00-04:00"
  },
  "internalReference": 485
}
```

An approved transaction returns a response like the following:

```json
{
  "status": {
    "status": "APPROVED",
    "reason": "00",
    "message": "Approved",
    "date": "2026-07-31T10:16:01-04:00"
  },
  "internalReference": 485,
  "reference": "ATHMV-ORDER-1001",
  "paymentMethod": "ATHMV",
  "franchise": "athmv",
  "franchiseName": "ATH Móvil",
  "amount": {
    "currency": "USD",
    "total": 10
  },
  "authorization": "000000",
  "provider": "ATH-MOVIL"
}
```

While the status is `PENDING`, repeat the query at a controlled interval. Stop querying when you receive `APPROVED`, `REJECTED`, or `FAILED`, or when the reported expiration is reached. If a query times out, keep the transaction pending and query again; do not automatically create another charge.

## Validations and considerations {{ id: 'validations' }}

| Field or condition | Validation |
| --- | --- |
| `payment.amount.currency` | Must be `USD`. |
| `payment.amount.total` | Must be greater than zero after applying taxes and amount details. |
| `payer.mobile` | Required for Gateway and must include `+1` and a Puerto Rico area code. |
| `instrument.redirection.paymentMethod` | Must be exactly `ATHMV` in Gateway. |
| `paymentMethod` | Use `ATHMV` in Webcheckout to restrict the session to this payment method. |
| Merchant MCC | Must be configured for the site before processing transactions. |
| Initial status | A `PENDING` response means the charge was received, not approved. |
| `redirection.processURL` | Available only in sandbox; production integrations must not depend on it. |

Subsequent operations available for a transaction depend on its status and the site configuration. For refunds or reversals, see [Operations on a transaction](/en/gateway/api/reference/transaction#transaction-request).

## Sandbox test cases {{ id: 'sandbox-test-cases' }}

For test sites, the simulator determines its behavior from `payer.mobile`. Always send the international `+1` prefix; without it, the expected test case will not be activated.

| Phone | Expected result |
| --- | --- |
| `+19391111114` | The query ends in `APPROVED`. |
| `+19391111112` | The query ends in `REJECTED` due to cancellation. |
| `+19391111113` | The query ends in `FAILED`. |
| `+19391111111` | The transaction remains `PENDING`. |
| `+19391111117` | The query ends in `FAILED` due to an expired token. |
| `+19391111120` | The query simulates a timeout and the transaction remains `PENDING`. |
| `+19391111178` | Processing fails immediately due to an expired token. |
