## Possible responses {{ id: 'reverse-responses' }}

<Row>
    <Col>
        These are the possible responses of the service and their cause. All of them include the `status` object; only an approved reversal also includes the `payment` object.

        | Scenario | HTTP | `status` | `reason` | `message` | Cause |
        | --- | --- | --- | --- | --- | --- |
        | Reversal approved | 200 | `APPROVED` | `00` | Approved | The reversal was processed successfully. Includes the `payment` object. |
        | Reversal pending | 200 | `PENDING` | `?-` | Depends on the provider | The acquirer or provider reports that the reversal is in process. |
        | Reversal rejected by the provider | 200 | `REJECTED` or `FAILED` | Provider code | Provider message | The acquirer or provider rejected the reversal. |
        | Invalid reference | 400 | `FAILED` | `request_not_valid` | Invalid reference: must be a string between 1 and 32 characters | `internalReference` was not sent or is not numeric. Although the message indicates a string of 1 to 32 characters, the validation requires a numeric value. |
        | Invalid amount | 400 | `FAILED` | `request_not_valid` | The amount it is bad formed, not numeric total | `amount` was sent and `amount.total` is not numeric. |
        | Amount sent with negative or zero total | 400 | `FAILED` | `request_not_valid` | The amount base its required to the payment | In a reversal `amount` is optional. The error occurs only if it is sent with a `total` less than or equal to zero. |
        | Transaction does not exist | 400 | `FAILED` | `request_not_valid` | The transaction you search does not exists | There is no transaction with the `internalReference` sent. |
        | Transaction from another site | 400 | `FAILED` | `request_not_valid` | The session with that identification does not exists | The transaction belongs to another site. |
        | No response from the gateway | 400 | `FAILED` | `transaction_request_error` | The service could not be reached, please try again in a few moments | The request is valid, but no response was obtained from the gateway due to a timeout or connection problems. |
        | Gateway rejects the reversal | 400 | `FAILED` | `transaction_request_error` | La transacción no puede ser procesada<br />The authorization code provided does not match<br />Transaction already refunded<br />The transaction already has a reverse in process<br />Another operation is being processing<br />Transaction is not conciliated<br />The currency provided is invalid<br />The service does not support reverse<br />The payment method associated with the transaction is no longer enabled | The gateway answered with an HTTP error due to a business validation, such as an incorrect authorization, an already refunded transaction or a reversal in process. Checkout keeps the gateway message, but returns `transaction_request_error` instead of the original code. |
        | Payment method without reversal support | 400 | `FAILED` | `0` | Reverse transaction not supported yet | The payment method does not support reversals (Breb, PSE, PSE Nequi, ALIA and RedirectRest). |
        | Internal error | 503 | `FAILED` | `MN` | Maintenance service | Error in Placetopay services. |

        <Note>
            The availability of reversals may vary depending on the payment method, country, and/or provider used.
            Authentication errors are described in [Possible errors](/en/checkout/authentication#possible-errors) and [Frequent errors](/en/checkout/authentication#frequent-errors).
        </Note>
    </Col>
