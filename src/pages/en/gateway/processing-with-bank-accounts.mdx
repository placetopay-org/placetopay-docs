# Processing with bank accounts

To process transactions using a bank account as a payment instrument, it is necessary to implement the account payment instrument that allows defining the account data to be used, as well as the mechanisms to validate the account using account validation services such as: Account Validator.

## Resources

#### [Processing API](/en/gateway/api/reference/transaction)
#### [Account validator API](/en/account-validator)

## Bank account instrument

```json
 "account": {
    "bankName": "Test Bank",
    "bankCode": "0001234",
    "accountType": "SAV",
    "accountNumber": "4111111111111111"
  }
```

### Type of bank accounts

Type | Description
-----|----------
 SAV | Personal savings account
 DDA | Personal checking account
 CCD | Business account

## Account validation

To ensure security in bank account processing, it is recommended to use the Account Validator bank account validation service.

With this service, before initiating the payment, the account owner is required to perform a verification operation in a graphical interface.

Once the account owner completes this process, the service is consulted via API and the Account object is obtained with a verification code delivered by the service.

The processing API will be in charge of validating this code delivered by Account Validator and determining if the account has passed the validations, if not, the processing will not continue.

## Tokenization

A bank account can be tokenized in such a way that charges can be made to said account without the account owner being present.

In this flow, once the account has been validated, a token that represents the account can be generated and can be used to make new transactions.

Check the section [Tokenization](/en/gateway/api/reference/tokenize) of the API.

## ACH Return simulator

> **Important:** this simulator is exclusive to the test/certification (`test`) environment. It does not reproduce the real ACH return generation process between Placetopay and the banking networks, and it **does not imply any kind of certification** between Placetopay and the return processes. Its sole purpose is to let merchants validate, in test, the events, statuses and notifications (Webhooks) they would receive if a real ACH return occurred in production.

In production, ACH Returns are generated by processes external to Placetopay and are later captured, enriched and notified (for example, via Webhooks). This behaviour cannot be truly replicated in the test environment, so 3 additional mock accounts were enabled, exclusive to the `account` instrument (ACH Bank Debit), with a fixed (non-configurable) behaviour:

Account | Number | Expected behavior
--------|--------|------------------
A | `1111111111` | The transaction is approved and remains approved.
B | `2222222222` | The transaction is rejected immediately.
C | `370366438` | The transaction is approved and, after a few minutes, an ACH Return is automatically generated with the NACHA return reason code **R09 (Uncollected Funds)**.

### Account C behavior

When the simulated return for account C is generated, a child transaction of type `CHARGEBACK` is created and linked to the original transaction, and it is notified through the same [ACH return Webhook](/en/payments/external-redirects/ach-bank-debit#webhook-notification-for-ach-returns) used in production. The relevant fields are populated as follows:

Field | Value
------|------
`originalTransactionDate` | Date of the original (parent) transaction.
`clientBankAccountNumber` | Bank account number of the original transaction (`370366438`).
`bankRoutingNumber` | Bank routing number of the original transaction.
`processBatchId` | Simulated batch identifier.
`returnId` | Simulated return identifier.
`returnDate` | A date after the original transaction's date.
`returnData` | The first 9 digits in zero followed by the authorization number (CUS) of the original transaction.
`reason` | `R09` (Uncollected Funds).

These simulated transactions are visible both in the administrative Panel and in the query APIs, just like a real return.
