## Sync a merchant {{ id: 'sync-merchant', tag: 'PUT', label: '/api/merchants/{coreId}' }}

<Row>
  <Col>
    Creates the merchant in PAR or updates the one that already exists with that `coreId`, together with its merchant partner. It is idempotent: repeating the same request leaves the same result. More detail in [Merchants and sites](/en/par/administration/merchants-and-sites).

    <Note type="warning">
      The merchant is active only if `merchant.status` is `ACTIVE` **and** `settings.enabled` is `true`. If it ends up inactive, or if its `authorizationCode` changes, PAR revokes the open sessions of its partner.
    </Note>

    <ApiReader
      path="/api/merchants/{coreId}"
      type="params"
      api={props.refs}
    />

    <ApiReader
      path="/api/merchants/{coreId}"
      method="put"
      type="header"
      api={props.refs}
    />

    <ApiReader
      path="/api/merchants/{coreId}"
      method="put"
      api={props.refs}
    />

  </Col>
  <Col sticky>
    <CodeGroup title="Request" tag="PUT" label="/api/merchants/{coreId}">
```bash {{ title: 'Sync the merchant' }}
curl --request PUT \
  --url '{URL_BASE}/api/merchants/10' \
  --header 'Accept: application/json' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Bearer {YOUR_TOKEN}' \
  --data '{
    "issuer": "operator@example.com",
    "locale": "en",
    "merchant": {
      "coreId": 10,
      "name": "Test merchant",
      "authorizationCode": "MerchantSecret123",
      "documentType": "NIT",
      "document": "900123456",
      "city": "Santiago",
      "country": "CL",
      "status": "ACTIVE"
    },
    "settings": {
      "enabled": true,
      "requiresAutopayApproval": true,
      "notificationEmail": "notifications@example.com"
    }
  }'
```
    </CodeGroup>
  </Col>
</Row>

## Sync a site {{ id: 'sync-site', tag: 'PUT', label: '/api/sites/{coreId}' }}

<Row>
  <Col>
    Creates the site in PAR or updates the one that already exists with that `coreId`. The merchant it belongs to must be synced beforehand. The response returns the site's `commerceCode`: it is the value the merchant sends in the `Commercecode` header. More detail in [Merchants and sites](/en/par/administration/merchants-and-sites).

    <Note>
      The site is active only if `site.status` is `ACTIVE` **and** `settings.enabled` is `true`. If you do not send `site.commerceCode`, PAR keeps the current one or generates a new one.
    </Note>

    <ApiReader

## Update an issuer partner {{ id: 'update-partner', tag: 'POST', label: '/api/partners/{partnerId}' }}

<Row>
  <Col>
    Replaces the configuration of a partner of type `issuer`: always send all the required fields, not just the ones that change. If the partner is a merchant partner, it responds `422`: those partners are updated when you [sync the merchant](#sync-merchant).

    <Note type="warning">
      If you change the `secretKey` or deactivate the partner with `enabled: false`, PAR revokes its open sessions. To rotate the key, send the new one in `secretKey` and hand it to the issuer.
    </Note>

    <ApiReader
      path="/api/partners/{partnerId}"
      type="params"
      api={props.refs}
    />

    <ApiReader
      path="/api/partners/{partnerId}"
      method="post"
      type="header"
      api={props.refs}
    />

    <ApiReader
      path="/api/partners/{partnerId}"
      method="post"
      api={props.refs}
    />

  </Col>
  <Col sticky>
    <CodeGroup title="Request" tag="POST" label="/api/partners/{partnerId}">
```bash {{ title: 'Rotate the secret key' }}
curl --request POST \
  --url '{URL_BASE}/api/partners/7' \
  --header 'Accept: application/json' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Bearer {YOUR_TOKEN}' \
  --data '{
    "name": "Test bank",
    "type": "issuer",
    "userDocumentType": "CLRUT",
    "enabled": true,
    "allowedIps": ["192.0.2.10"],
    "allowedFrameOrigins": ["https://www.example.com"],
    "secretKey": "NewSecret123456"
  }'
```

```bash {{ title: 'Deactivate the partner' }}
curl --request POST \
  --url '{URL_BASE}/api/partners/7' \
  --header 'Accept: application/json' \

  --header 'Authorization: Bearer {YOUR_TOKEN}' \
```
