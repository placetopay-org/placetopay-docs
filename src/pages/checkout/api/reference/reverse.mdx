## Posibles respuestas {{ id: 'reverse-responses' }}

<Row>
    <Col>
        Todas las respuestas incluyen el objeto `status` con las propiedades `status`, `reason`, `message` y `date`. Solo el reverso aprobado incluye además el objeto `payment`. Cuando el gateway rechaza una solicitud por una validación de negocio, Checkout conserva el mensaje pero responde `transaction_request_error`; el estado `REJECTED` o `PENDING` con código del proveedor aplica solo cuando el adquirente o proveedor responde con ese estado.

        | Escenario | HTTP | `status` | `reason` | `message` | Causa |
        | --- | --- | --- | --- | --- | --- |
        | Reverso aprobado | 200 | `APPROVED` | `00` | Aprobada | El reverso fue procesado correctamente. Es el único caso cuya respuesta incluye el objeto `payment`; en los demás solo viene `status`. |
        | Reverso pendiente | 200 | `PENDING` | `?-` | Depende del proveedor | El adquirente o proveedor respondió que el reverso está en proceso. Consulta el estado de la transacción más adelante. |
        | Adquirente o proveedor rechaza el reverso | 200 | `REJECTED` o `FAILED` | Código del proveedor | Mensaje del proveedor | El adquirente o proveedor del medio de pago respondió con ese estado. |
        | Referencia inválida | 400 | `FAILED` | `request_not_valid` | Referencia no válida, debe ser de tipo string entre 1 a 32 caracteres | `internalReference` ausente o no numérico. La validación real exige un valor numérico, aunque el mensaje indique un string de 1 a 32 caracteres. |
        | Monto inválido | 400 | `FAILED` | `request_not_valid` | El monto está mal formado, no es númerico [total] | Se envió `amount` y `amount.total` no es un número. |
        | Monto enviado con total negativo o cero | 400 | `FAILED` | `request_not_valid` | Se requiere el valor base para el pago | En reversos `amount` es opcional; este error solo ocurre si se envía con `total` menor o igual a 0. |
        | Transacción no existe | 400 | `FAILED` | `request_not_valid` | No existe la transacción que busca | No existe una transacción con la `internalReference` enviada. |
        | Transacción de otro sitio | 400 | `FAILED` | `request_not_valid` | La sesión que busca no existe | La transacción pertenece a un sitio diferente al autenticado. |
        | Sin respuesta del gateway | 400 | `FAILED` | `transaction_request_error` | No se ha logrado conexión con el servicio externo, por favor intenta en unos minutos | La solicitud estaba bien formada, pero Checkout no obtuvo respuesta del gateway: tiempo de espera agotado, problema de red o respuesta de error sin detalle. Verifica el estado de la transacción antes de reintentar. |
        | Gateway rechaza el reverso | 400 | `FAILED` | `transaction_request_error` | Mensaje informado por el gateway | El gateway respondió con un error HTTP y un `status` por una validación de negocio. Checkout conserva el mensaje, pero responde `transaction_request_error` en lugar del código original. Mensajes posibles:<br />**La transacción no puede ser procesada**: la transacción no está aprobada.<br />**El código de autorización no concuerda**.<br />**La transacción ya ha sido reembolsada**.<br />**La transacción ya tiene un reverso en proceso**.<br />**Se está procesando otra operación**.<br />**La transacción aún no se ha conciliado**: el `amount.total` enviado no es el valor total reversable.<br />**La moneda proporcionada es inválida**.<br />**El servicio no soporta reversos**.<br />**El medio de pago asociado con la transacción ya no se encuentra habilitado**. |
        | Medio de pago sin soporte de reverso | 400 | `FAILED` | `0` | Reverse transaction not supported yet | El medio de pago no soporta reversos (Breb, PSE, PSE Nequi, ALIA y RedirectRest). |
        | Error interno | 503 | `FAILED` | `MN` | Servicio en mantenimiento | Error en los servicios de Placetopay. |

        <Note>
            La disponibilidad de reversos depende del medio de pago, país y/o proveedor.
            Los errores de autenticación (`auth`) se describen en [Posibles errores](/checkout/authentication#possible-errors) y [Errores frecuentes](/checkout/authentication#frequent-errors) de Autenticación.
        </Note>
    </Col>
